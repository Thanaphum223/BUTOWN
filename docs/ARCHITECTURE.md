# โครงสร้าง TownTrack

## ข้อกำหนดที่ยืนยันแล้ว
- ใช้ฐานข้อมูลของตัวเองก่อน แยกจาก GovCenter
- ไม่อนุมัติทรัพยากรที่ลำดับใดก็ตาม: TERMINATED ทั้งคำร้อง และยกเลิกงานที่ค้างใน Transaction เดียวกัน
- ค้นหาเคสประเภทเดียวกันที่ยังไม่จบในรัศมี 100 เมตร ใช้ ST_DWithin บน geography
- ประชาชนอื่นเห็นเฉพาะรหัส ประเภท สถานะ และพิกัดปัดทศนิยม 3 ตำแหน่ง ไม่เห็นชื่อ หัวข้ออิสระ รายละเอียด ที่อยู่จริง รูป หรือเอกสาร (การปัดพิกัดเป็นการประมาณ ไม่ใช่การรับประกันระยะพราง 100 เมตร)

## โครงสร้าง
React SPA → API /api → Spring Boot แบบระบบเดียวแบ่งโมดูล → PostgreSQL/PostGIS
ไฟล์อยู่นอก Web Root ใน FILE_ROOT เก็บ metadata, SHA-256 และความสัมพันธ์ในฐานข้อมูล ดาวน์โหลดผ่าน API ตรวจสิทธิ์เท่านั้น
LINE เป็น Integration เสริม ปิดโดยปริยาย GovCenter ยังไม่มี implementation

## ความสัมพันธ์ข้อมูล
- municipality 1:N department, app_user, workflow_version, category, complaint
- category เลือกหน่วยงาน Workflow version SLA และ fields แบบ JSON
- complaint เก็บผู้แจ้ง หน่วยงาน หัวหน้า เจ้าหน้าที่ พิกัด answers และ form_schema snapshot รวมถึง workflow_id และ due_at ณ วันที่ยื่น
- complaint 1:N work_order; มีงาน active ได้ 1 งานต่อคำร้องด้วย Partial Unique Index งานที่ปฏิเสธคงประวัติไว้
- field_team มีสมาชิกและตัวแทน; การมอบหมายคัดลอกสมาชิกลง work_member เพื่อไม่ให้การเปลี่ยนทีมกระทบสิทธิ์งานเก่า
- work_order 1:N field_report แต่ละฉบับเก็บเป็นแถวใหม่ ไม่เขียนทับ
- resource_request 1:N resource_revision, approval_assignment
- review เก็บผลตรวจเอกสารและรายงานพร้อมเหตุผล
- audit_event เก็บเหตุการณ์แบบเพิ่มอย่างเดียว มี Trigger ป้องกัน UPDATE/DELETE (ผู้ดูแล DB ยังมีอำนาจแก้โครงสร้าง ต้องมีการควบคุมสิทธิ์และสำรองแยก)
- follower เชื่อมประชาชนกับคำร้องที่ติดตาม ไม่ให้สิทธิ์อ่านรายละเอียดเต็ม
- notification เป็นการแจ้งเตือนในระบบ; notification_delivery เป็นคิว LINE ใน Transaction เดียวกับการเปลี่ยนสถานะ

## ตารางสิทธิ์
| บทบาท | ขอบเขตอ่าน | การกระทำหลัก |
|---|---|---|
| ประชาชน | คำร้องของตัวเอง / ข้อมูลสรุปเคสใกล้เคียง | ยื่นเรื่อง แนบหลักฐานขณะ NEW ติดตาม/เลิกติดตาม |
| เจ้าหน้าที่ | คำร้องในหน่วยงานตน หรือคำร้องยังไม่มีหน่วยงาน | รับ/ปฏิเสธเรื่อง ตรวจข้อเสนอ เลือกผู้อนุมัติ ตรวจรายงาน ปิดเรื่อง |
| หัวหน้า | คำร้องที่ได้รับมอบหมายให้ตน | จัดทีม มอบหมายงาน เสนอทรัพยากร ตรวจรายงาน |
| ผู้ลงพื้นที่ | งานที่ได้รับมอบหมายหรือเป็นสมาชิกทีม ณ เวลามอบหมาย | ตัวแทนทีมรับ/ปฏิเสธ เริ่มงาน ขอทรัพยากร ส่งรายงาน; สมาชิกดูงานได้ |
| ผู้อนุมัติ | คำร้องที่มีคำขอทรัพยากรมอบหมายให้ตนเป็นผู้อนุมัติปัจจุบัน | อนุมัติ/ไม่อนุมัติเฉพาะลำดับของตน |
| Admin | ข้อมูลในเทศบาลตน | จัดผู้ใช้ หน่วยงาน ประเภทปัญหา และเผยแพร่ Workflow; ไม่ข้ามสิทธิ์ไปอนุมัติงาน |

ไม่มี role จาก Frontend ที่เชื่อถือได้ Backend อ่านผู้ใช้และขอบเขตจาก DB ทุกครั้ง UUID เพียงอย่างเดียวไม่ใช่การควบคุมสิทธิ์

## Workflow และความสอดคล้อง
NEW → TRIAGED → ASSIGNED → ACCEPTED → IN_PROGRESS → LEADER_REVIEW → OFFICER_REVIEW → RESOLVED → CLOSED
- ASSIGNED → DECLINE → TRIAGED เพื่อจัดทีมใหม่
- ACCEPTED → REQUEST_RESOURCE → RESOURCE_DRAFT → RESOURCE_CHECK → RESOURCE_APPROVAL → READY → IN_PROGRESS
- เอกสารไม่ครบ → RESOURCE_REVISION → ส่ง proposal ฉบับใหม่
- ไม่อนุมัติที่ลำดับใด → TERMINATED
- หัวหน้าส่งกลับ → FIELD_REVISION → รายงานฉบับใหม่
- เจ้าหน้าที่ส่งกลับ → LEADER_REVISION → หัวหน้าส่งต่ออีกครั้งหรือคืนทีมแก้ไข
- ไม่รับเรื่อง → REJECTED

ใช้ SELECT FOR UPDATE ของคำร้อง และ version ที่ Client ส่งมา หาก version เก่าตอบ 409 ทุกการเปลี่ยนสถานะและ Audit อยู่ใน Transaction เดียวกัน ลำดับอนุมัติ 1–5 คนไม่ซ้ำกัน โดยคนถัดไปทำได้หลังคนก่อนผ่านเท่านั้น

## การตั้งค่าและขอบเขตความยืดหยุ่น
- ตั้งหน่วยงาน SLA ช่องข้อมูลข้อความเพิ่มเติม และ Workflow ที่ใช้กับประเภทปัญหาได้
- เผยแพร่ Workflow เวอร์ชันใหม่พร้อมจำนวนลำดับอนุมัติทรัพยากร 1–5
- คำร้องเดิมยึด Workflow version, SLA deadline และแบบฟอร์ม snapshot เดิม
- รูปแบบเส้นทางหลักตาม Flow ที่ตกลงไว้ ไม่ใช่ตัววาด BPMN อิสระ และไม่รันโค้ดที่ผู้ดูแลใส่เอง
- ช่องเพิ่มเติมรุ่นนี้เป็นข้อความ; ถ้าต้องการตัวเลือกซับซ้อน ตารางรายการงบ หรือเงื่อนไขข้ามช่อง ต้องเพิ่ม schema/validator ที่มี version
- ตัวแทนทีมทำรายการหลัก สมาชิกอ่านข้อมูล; การรับงานรายคนทุกสมาชิกหรือแยกงานหลายทีมพร้อมกันยังไม่อยู่ในรุ่นนี้
- อนุมัติคือการบันทึกผลภายในระบบ ไม่ใช่ลายเซ็นดิจิทัลหรือระบบเบิกจ่ายงบประมาณ

## GovCenter
GovCenterPort เป็น interface ไม่มี fake endpoint ต้องได้ API contract, วิธี SSO, รหัสเทศบาล/หน่วยงาน, หลักเกณฑ์เจ้าของข้อมูล, การแก้ข้อมูลขัดแย้ง และแนวทางย้ายบัญชีก่อน implementation ใช้ integration_reference และ external_id แยกจาก UUID ภายใน ห้ามใช้ external ID เป็นสิทธิ์โดยตรง
